# Отчёт по лабораторной работе №1 (BDSnowflake)

Работа выполнена студентом МАИ группы М8О-205СВ-25 Рудневом Виктором Владимировичем.

## Цель

Преобразовать исходные CSV (покупатели, продавцы, магазины, товары, поставщики, продажи) в аналитическую модель «снежинка» в PostgreSQL.

## Шаги выполнения

1. Подготовлен `docker-compose.yml`: PostgreSQL 16 и сервис `migrate` (golang-migrate).
2. Миграции в `migrations/` парами `*.up.sql` / `*.down.sql`:
   - `001` — таблица `mock_data` (посадка CSV, не модель);
   - `002` — загрузка 10 файлов;
   - `003` — DDL снежинки в схеме `star`;
   - `004` — заполнение измерений и факта из `mock_data`.
3. Применены командой `up` при старте compose.
4. Проверены объёмы и целостность связей.

## Обоснование модели

Факт — одна продажа: `sale_quantity`, `sale_total_price`, дата и ссылки на покупателя, продавца, товар, магазин.

Снежинка (нормализация измерений):

- страны и города вынесены отдельно (`dim_country`, `dim_city`);
- у покупателя отдельно тип и порода питомца;
- у товара — категория, бренд, цвет, размер, материал, категория питомца и поставщик.

Исходные `id` / `sale_*_id` как глобальные ключи не подходят: в каждом файле они идут с 1 по 1000 и относятся к разным сущностям. Для сторон взят email, для товара — `product_nk` (md5 по атрибутам + email поставщика), PK везде суррогатные.

Сумму продажи из цены и количества не пересчитывал: в исходнике они почти не совпадают, оставил как есть.

## Конфигурация

Параметры Postgres задаются в `.env` рядом с `docker-compose.yml`. В репозиторий этот файл не кладётся, есть только шаблон `.env_example`.

Перед первым запуском:

```bash
copy .env_example .env
```

В `.env` четыре переменные:

| Переменная | Зачем |
|------------|--------|
| `POSTGRES_USER` | пользователь БД |
| `POSTGRES_PASSWORD` | пароль |
| `POSTGRES_DB` | имя базы |
| `POSTGRES_PORT` | порт на хосте (внутри контейнера всегда 5432) |

В шаблоне стоят локальные значения: пользователь `postgres`, пароль `postgres`, база `pet_store`, порт `5432`. Для сдачи их можно не менять. Если порт 5432 занят — поменять только `POSTGRES_PORT`.

Дальше из каталога `BDSnowflake`:

```bash
docker compose up -d
```

Compose поднимает Postgres и прогоняет `migrate up`. Откат последней версии: `docker compose run --rm migrate down 1`. Полный откат: `docker compose run --rm migrate down -all`.

`mock_data` — исходные 10000 строк из CSV, как в задании. Модель — схема `star`. Подключение: `localhost` и порт из `POSTGRES_PORT`, база и логин из `.env`.

Повторная инициализация с нуля: `docker compose down -v && docker compose up -d`.
